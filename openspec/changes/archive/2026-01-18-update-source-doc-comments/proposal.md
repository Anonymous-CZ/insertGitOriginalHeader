# Change: 完善核心源码注释与文件头描述

## Why
目前核心源码的文件头 `@Description` 多为空，且关键函数缺少系统化的 JSDoc 注释，不利于维护、测试与后续扩展（尤其是 VS Code Extension 与 Git 命令交互部分）。

本变更旨在为核心文件补齐一致、可读、可维护的注释与描述，同时尽量不在函数内部加入碎片化注释，保持代码清爽。

## What Changes
- 为以下核心文件补齐“简介明了”的文件头 `@Description`：
  - `src/extension.ts`
  - `src/header.ts`
  - `src/commentStyle.ts`
  - `src/dateTime.ts`
  - `src/author.ts`
- 为对外/关键函数补齐详细 JSDoc（包含意图、参数、返回、边界行为/兜底策略、典型示例）。
- 为关键变量补齐 1 行内的行注释（优先 `//`），强调“为什么/约束/单位/格式”，避免解释显而易见的实现细节。
- 保持函数内部注释最少：仅在“非直观的边界处理/命令拼接转义/时间选择规则”等确实复杂处补充。

## Non-Goals
- 不改变任何运行时行为、命令 ID、配置 schema、输出格式。
- 不重构代码结构（除非为注释准确性进行极小范围的命名微调；如发生需要在单独提议中进行）。
- 不新增用户可见功能。

## Impact
- Affected specs: `git-original-author-header`（新增非功能性“源码注释/可维护性”要求；不改变运行时行为）。
- Affected code: `src/*.ts`（仅注释与文件头描述变更）。
- Risk: 低；主要风险是注释与实际行为不一致，因此需要以测试与现有行为为准校对。

## Acceptance Criteria
- 以上 5 个文件的 `@Description` 均为一句话（或一句话 + 极短补充），说明该文件职责与边界。
- 每个导出函数均有 JSDoc，至少覆盖：
  - 函数意图（做什么/不做什么）
  - 参数含义与约束
  - 返回值/失败兜底策略
  - 至少 1 个关键边界示例或场景说明（如：unknown 行为、空字符串、无法解析时间）
- 变量注释遵循“1 行内、优先 `//`、解释约束/格式/原因”。
- 不新增 ESLint/TypeScript 错误；`pnpm test` 通过。
