## Context
扩展当前通过 `git log --reverse ... -1` 获取文件的最早提交作者与时间，并将该时间直接写入文件头的 `@Date`。

在某些工作流里，文件可能先存在于本地（或从其它来源拷贝），之后才被 `git add` 并首次提交；此时文件系统的创建时间可能早于 Git 的首次提交时间。

## Goals / Non-Goals
- Goals:
  - 在可用条件下，`@Date` 使用“Git 原始提交时间”和“文件创建时间”中更早的时间。
  - 兼容跨平台：当文件系统不提供可靠创建时间时，自动回退到 Git 时间。
  - 不引入外部依赖（使用 Node.js 内置 `fs`）。
- Non-Goals:
  - 推断“文件创建者”或变更 `@Author` 语义。
  - 根据文件类型自动切换注释模板。

## Decisions
- 时间来源：
  - Git 原始提交时间：现有逻辑产出字符串格式 `YYYY-MM-DD HH:mm:ss`。
  - 文件创建时间：使用 `fs.stat()` 的 `birthtime`（或等价字段），并转换为同样格式。
- 时间选择规则：
  - 若两者均可解析为有效时间戳，取最小值。
  - 若仅一者可用，使用可用者。
  - 若两者都不可用，使用兜底值（保持现有行为的兜底：`1970-01-01 00:00:00`）。
- 解析/格式化：
  - 统一在代码中用 `Date` 对象进行比较（`getTime()`）。
  - 输出格式固定为 `YYYY-MM-DD HH:mm:ss`。

## Risks / Trade-offs
- `birthtime` 在部分文件系统/平台上可能不是“真正的创建时间”（可能等同于 `ctime` 或不可靠）。
  - 缓解：当检测到 `birthtime` 不可用或异常（例如无效日期/epoch 0）时回退到 Git 时间。
- Git 时间字符串不含时区信息。
  - 缓解：使用本地时间进行解析与比较；因为两者都来自本地环境，对用户而言一致即可。

## Open Questions
- 当文件创建时间早于 Git 时间时，是否需要同步调整 `@Author`？（本提议不调整，仍以 Git 原始作者为准）
